# 피지컬 AI 연구 수집 운영

[English](research-monitor.en.md) · 한국어

[GitHub Actions 실행 기록](https://github.com/james-joobs/awesome-nvidia-physical-ai/actions/workflows/collect-research.yml) · [최신 수집 보고서](https://github.com/james-joobs/awesome-nvidia-physical-ai/blob/research-reports/latest.md)

GitHub Actions는 매일 09:17 KST에 공식 출처에서 변경 후보를 수집합니다. Actions에서 **Run workflow**를 선택해 수동으로 실행할 수도 있습니다. 보고서는 `research-reports` 브랜치에 저장됩니다.

- `latest.md`에는 최근 발견·변경, 누적 검토 대기열, 출처별 확인 상태가 나옵니다. 금요일 스냅샷은 `weekly.md`에 저장됩니다. `state.json`은 수집 근거와 대기열을, `review-state.json`은 주간 검토 결정을 보관합니다.
- 카탈로그에서 찾은 공식 저장소와 지정 저장소의 릴리스·라이선스, NVIDIA 관련 조직의 새 공개 저장소, Hugging Face 모델·데이터셋·Papers, NVIDIA 기술 블로그와 Research 사이트맵, SIL·GEAR·Seattle Robotics Lab의 연구 목록을 확인합니다. arXiv는 `cs.RO`·`cs.CV`·`cs.LG`의 관련 연구를 조회합니다.
- 새 수집 경로는 최근 90일을 소급 조회합니다. 이후에는 마지막 성공 시점과 겹치는 기간을 다시 확인합니다. API 목록은 페이지를 넘겨 조회하며, 조회 상한이나 파싱 오류에 도달하면 출처를 정상으로 기록하지 않습니다. 피드에서 이미 빠진 과거 항목까지 복구할 수 있는 것은 아닙니다.
- 최초 발견일·최근 확인일과 원문의 발표·수정일을 구분합니다. 사이트맵 수정일이나 수집일을 논문 발표일로 바꾸지 않습니다. 날짜가 없는 연구 목록도 최초 발견을 기록할 수 있습니다.
- 금요일에는 누적 대기열에서 후보를 다시 검증합니다. 같은 논문의 arXiv·Hugging Face Papers·공식 프로젝트 페이지는 명시적인 연결 근거가 있을 때 묶습니다. 단순히 같은 라이브러리를 사용하는 다른 연구는 합치지 않습니다.
- 같은 URL에서도 버전·라이선스·접근 조건·배포 링크가 달라지면 새 검토 사건으로 남깁니다. 기존 링크가 있다는 이유로 변경을 무시하지 않습니다. 주간 선정 한도를 넘긴 후보는 다음 주에도 남습니다.
- NVIDIA 공식 페이지나 공식 소유자의 저장소와 연결된 후보를 먼저 검토하고, 같은 우선순위에서는 오래 기다린 후보부터 처리합니다. 기존에 사람이 정리한 행은 자동 교체하지 않고, 새 근거를 붙여 수동 검토 대상으로 남깁니다.
- 공식 저장소·릴리스, 모델·데이터 카드 및 연구 원문에서 확인한 공개 범위와 이용 조건을 같은 출처를 사용한 영문·한국어 초안에 기입합니다. 확인할 수 없는 연구 코드·가중치는 미확인으로 표시합니다. 카탈로그에 자동으로 추가하는 코드·가중치·데이터는 라이선스 근거를 확인한 항목입니다.
- 사이트 빌드·검색 테스트·실습 검증을 통과하면 `automation/research-YYYY-MM-DD` 브랜치로 주간 초안 PR을 엽니다. 새로 반영할 내용이 있을 때 PR이 생성됩니다. 운영자가 검토 후 `main`에 병합하면 Pages에 배포됩니다.
- PR에 들어간 사건 ID로 제안·병합·거절 상태를 다시 확인합니다. 병합하지 않고 닫은 제안을 자동으로 다시 올리지 않으며, 이후 새 변경은 별도 후보가 됩니다. 검증을 통과하고 PR 생성이 성공한 뒤에만 제안 상태를 저장합니다.
- Actions에서 **Run workflow**의 **review_preview**를 선택하면 수집, 초안 작성, 검증을 실행합니다. 변경분과 `review-state.json`은 **weekly-research-review** 아티팩트에서 볼 수 있습니다. 미리보기는 실제 PR을 만들거나 검토 결정을 확정하지 않습니다.
- 수집기 변경을 검증할 때는 검토 브랜치에서 `review_preview=true`로 실행할 수 있습니다. 이 경우 해당 브랜치의 코드로 검사하며, 공개 보고서 브랜치·PR·검토 상태를 쓰지 않습니다. `main`에서 실행한 미리보기는 수집 보고서만 저장합니다.

## 공개 범위와 대기열

논문, 코드, 가중치, 데이터의 공개 여부와 라이선스는 각각 확인합니다. 논문이 공개돼도 코드가 공개됐다고 표시하지 않으며, 논문 라이선스를 모델이나 코드에 적용하지 않습니다. 공식 페이지에 배포 링크가 없으면 **공식 배포 링크 미확인**으로 기록합니다. 연구를 소개하는 것과 바로 실행할 수 있는 실습을 제공하는 것은 별개입니다.

| 상태 | 의미 |
| --- | --- |
| `pending` | 아직 검토용 PR에 제안하지 않은 발견 또는 변경 |
| `deferred` | 근거 확인이나 기존 PR 처리를 기다리는 항목. 재확인 시점까지 보관 |
| `proposed` | 열린 검토용 PR에 포함된 항목 |
| `merged` | 문서에 반영됐거나 기존 문서의 기준 상태로 확인된 항목 |
| `rejected` | 병합하지 않고 닫힌 PR의 제안. 같은 사건은 반복 제안하지 않음 |

현재 선정 한도는 종류별로 적용하며, 한도 밖 항목은 삭제하지 않습니다. 확인할 수 없는 라이선스나 접근 조건은 수동 검토 사유로 남깁니다. 영문·한국어 초안은 동일한 검증 기록을 사용합니다.

## 수집 상태 확인

출처의 HTTP 응답뿐 아니라 목록 추출과 페이지 넘김도 검사합니다. 출처가 실패하면 이전 관측과 대기열을 보존합니다. 개별 출처 실패는 보고서와 Actions 경고에 표시하고, 3일 이상 이어지면 수리 필요 경고를 추가합니다. 다른 출처의 검증된 후보는 계속 검토할 수 있지만, 모든 출처가 실패하면 주간 제안을 중단합니다.

API 요청 제한이나 한 번의 조회 상한에 걸리면 부분 결과와 이어받을 위치를 보관합니다. 공식 프로젝트 페이지는 한 번에 최대 40개를 확인하며, 마지막 확인 시각을 저장해 다음 실행에서 나머지 페이지도 순환 확인합니다. 전체 출처가 실패한 실행의 보고서는 Actions 아티팩트에 남고, 공개 보고서 브랜치의 이전 정상 기록은 유지됩니다.

예약 실행은 지연되거나 누락될 수 있습니다. 마지막 실행 시각과 출처별 마지막 성공 시각을 함께 확인합니다. [GitHub 예약 실행 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

수집기와 대기열 회귀 검사는 다음 명령으로 실행합니다. BirdDreams처럼 `cs.CV`에 등록된 연구, 연구실 목록의 iframe·데이터 구조, 같은 프로젝트의 여러 출처, URL은 같지만 달라진 공개 조건 등을 검사합니다.

```sh
python3 -m unittest discover -s scripts -p 'test_research*.py'
```

## Mac에서 자동으로 받기

첫 보고서가 올라간 후 이 레포에서 아래 명령을 실행합니다.

```sh
./scripts/install-macos-research-sync.sh
```

기본 보관 위치는 `~/work/awesome-nvidia-physical-ai-reports/`입니다. 다른 위치는 절대 경로를 첫 인수로 전달합니다. 로그인할 때와 매시 07분·37분에 전용 체크아웃을 업데이트합니다. Mac이 꺼져 있는 동안에는 GitHub가 수집을 이어가고, 다음 로그인에서 보고서 브랜치의 최신 커밋을 받습니다.

보고서 체크아웃에서 읽거나 복사할 수 있습니다. 파일을 편집하면 안전한 빠른 감기 업데이트가 실패할 수 있습니다. 오류 기록은 `~/Library/Logs/physical-ai-research-sync.log`에 남습니다.
