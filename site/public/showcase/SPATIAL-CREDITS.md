## WorldGen → Isaac Sim · 2026-11-20

`worldgen-isaac.mp4` records a continuous contact, reverse and waypoint-recovery run inside our generated robotics laboratory. The recovery is scheduled at 4.0 and 5.6 simulation seconds; it is not a learned obstacle detector. `worldgen-isaac-blocked.mp4` and `worldgen-isaac-detour.mp4` are independent closer-camera comparisons. `worldgen-isaac-probes.mp4` shows live cube drops with the generated room hidden to inspect authored collisions.

All four are **native X11 screen recordings of Isaac Sim 6.2**, cropped to the viewport and encoded at 1× speed. They are not offline renders or USD trajectory replay. The wide overview uses OmniPBR emission display value 400 to reveal the baked panorama; the close takes use value 1. This is a display treatment, not recovered physical illumination. Window geometry, crop, trims, original recording hashes and published hashes are preserved in [the lab evidence](../../../labs/worldgen-isaac/).

The appearance derives from the WorldGen/FLUX robotics-lab output credited above. Our transform assumes a 1.5 m camera-to-floor height; metric scale was not measured. The imported visual mesh has 80,000 vertices and 158,802 triangles. We authored the differential-drive robot, 5×4 m local floor and added crate. There is no NVIDIA robot-asset redistribution. The generated furniture is not automatically collision-validated. The static generated-mesh and no-collider comparisons remain in the evidence.

The ZIP includes our reduced room geometry, panorama and authored scene setup; OmniPBR.mdl is resolved from the user's licensed Isaac Sim installation. No FLUX or other model weights are included. Isaac Sim and its MDL runtime retain NVIDIA's terms; original scripts, diagrams and robot geometry follow the repository MIT license. The original room's FLUX output terms retain their distinct scope. Source used for API behavior: [NVIDIA simulation fundamentals](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/physics/simulation_fundamentals.html), [6.2 API migration](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/migration_guides/isaac_sim_6_0/core_api_to_core_experimental.html), [multi-tick settings](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/sensors/isaacsim_sensors_multitick_rendering.html). This verified GUI recipe uses per-frame compatibility rendering; it does not claim multi-rate sensor validation.

## WorldGen moving obstacles · 2026-11-20

The `worldgen-dynamic-navigation` comparison and Korean variant show a 13-second excerpt of the previous permanent-map controller, then the complete updated-map gate run. The `-gate`, `-static` and `-cart` files are independent viewport takes. All are real native X11 recordings of Isaac Sim 6.2 at **1× speed**. The only edits are viewport cropping, encoding, controller labels and a labeled cut between comparison takes. Post-run figures are separate data visualizations.

Kinematic obstacle targets are applied through the physics tensor API. In this 6.2 per-frame compatibility recipe, a separate non-colliding visible prim follows the **measured PhysX transform each step**; the collider is hidden from RGB rendering and remains active for physics-range sensing. `render_position_xyz`, actual rigid-body poses and target poses are checked together. The display is not an offline trajectory replay. Empty debug paths are hidden; orange dots visualize remembered cells at the sensor's display plane. Only the corrected, synchronized captures under `~/physical-ai-grid/worldgen-dynamic-navigation-2026-11-20/films-v2/` are published.

The previous `Navigator` is preserved byte-for-byte from the preceding lab. The new controller adds clearing/expiry, route-continuity cost, stop supervision and axle-centered tracking with a larger margin. It receives range frames, ego pose, goal and measurement time, not the actuator schedule or obstacle transforms. A simulated one-second input gap is a separate recorded-data check. The test assumes ideal planar sensing, simulator localization and known flat-floor bounds; it does not model arbitrary human behavior or establish real-robot safety.

The scene still derives from the credited WorldGen/FLUX laboratory and its assumed scale. The authored actor, visual mirror, robot, controller and figures use repository MIT terms. Isaac Sim, Physics Raycast Sensor schemas and OmniPBR retain NVIDIA runtime terms; no runtime binaries or model weights are included in the USD ZIP. Full native windows, initial USD files, logs and scans remain on falconeyes-omen.
